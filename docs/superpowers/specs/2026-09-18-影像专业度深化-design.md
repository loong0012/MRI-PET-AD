# 影像专业度深化设计 (方案 A · 核心专业度跃迁)

- **日期**: 2026-09-18
- **项目**: ADScreen 阿尔兹海默病多模态影像智能筛查平台
- **期次**: 第 1 期 / 共 4 期 (4 期为：影像专业度深化 / 工作流与协作 / 数据与可信度 / AI 解释性与持续学习)
- **方案**: 方案 A — 核心专业度跃迁 (三大子能力)
- **状态**: 待用户审阅

---

## 1. 背景与目标

ADScreen 已完成 12 轮迭代，10 大模块功能齐全。对照市面优秀产品 (NeuroQuant longitudinal / BrainKey / 3D Slicer MPR / BrainLab) 识别出本项目在影像专业度维度的 10 项短板，归为 4 个方向，用户已选本期聚焦第 1 方向：**影像专业度深化**。

本期交付三大子能力，使 ADScreen 在影像专业维度达到市面中端产品水准：

1. **纵向影像量化** — 同患者多期影像的变化率计算与 NIA-AA 纵向进展分级 (对标 NeuroQuant longitudinal)
2. **DICOM 元数据增强** — 关键 DICOM 标签在前端的可视化呈现
3. **MPR 高级工具** — 窗宽窗位调节 + 距离/角度测量 + 三平面十字线联动

## 2. 非目标 (YAGNI)

明确不纳入本期：

- 不重构 DICOM→NIfTI 转换链路 (保留 `dicom_service.py` 现状)
- 不实现 MIP/VR 重建 (3D 体绘制已有 `VolumeRenderer.vue`)
- 不做血管/DTI 等非 AD 相关模态
- 不做多模态刚性+弹性配准链 (现有 MRI-PET 已配准 128³，满足需求)
- 不实现 DICOM SEG/SEG 容器对象导入
- 不做边缘 AI 推理 / 浏览器侧 WebGL 渲染
- 第 2-4 期方向 (工作流/数据可信度/AI 解释性) 不在本期实现

## 3. 设计原则

- **严格 TS，禁用 `any`** (前端)，类型从后端 schema 派生
- **PC-only**，不考虑移动端响应式
- **低饱和蓝灰医疗风格**，沿用现有 Tailwind 主题 token
- **不创建文档文件** (本 spec 例外，brainstorming 流程必需)
- **复用现有组件**：`MedicalViewport.vue` / `RoiAnnotationTool.vue` / `VolumeRenderer.vue` / ECharts / Three.js / ElementPlus
- **数据底座不变**：`CaseRecord.patient_no` + `exam_date` 已支持多期聚合，无需 schema 重构
- **渐进式**：真实影像不可用时回退到合成影像 + 模拟指标 (沿用现有 `imagingMeta.available` 模式)

## 4. 子能力 1：纵向影像量化

### 4.1 数据模型

新增 ORM 模型 `LongitudinalMetric`，文件 `ad-screen-backend/models/longitudinal.py`：

```python
class LongitudinalMetric(Base):
    __tablename__ = "longitudinal_metrics"
    id           = Column(Integer, primary_key=True, autoincrement=True)
    patient_no   = Column(String(60), index=True)      # 关联 CaseRecord.patient (patientNo)
    case_id      = Column(String(30), index=True)      # 关联 CaseRecord.id
    exam_date    = Column(String(30))                  # yyyy-mm-dd
    timepoint_idx = Column(Integer)                    # 该患者第几期 (0,1,2...)
    hippocampus_vol_l = Column(Float)                  # cm³，派生自 AnalysisResult.hippocampusVolumeL
    hippocampus_vol_r = Column(Float)
    mean_suv          = Column(Float)                  # 派生自 AnalysisResult.meanSUV
    cortical_thickness = Column(Float)                # 派生自 AnalysisResult.corticalThickness
    ventricle_vol     = Column(Float)
    mta_score         = Column(String(10))
    annual_rate_hv    = Column(Float, nullable=True)   # Δ cm³/年，单期 = null
    annual_rate_suv   = Column(Float, nullable=True)
    annual_rate_cort  = Column(Float, nullable=True)
    niaaa_stage       = Column(String(20), nullable=True)  # CN/MCI/AD-E/AD-L
    progression_note  = Column(Text, default="")
    compute_time      = Column(String(30), default="")
```

**派生策略**：不复制 `build_analysis` 全量输出。新增 `services/longitudinal_service.py::compute_metrics(patient_no)`，按需查询 `AnalysisResult` + `CaseRecord` 派生指标，结果缓存到 `LongitudinalMetric` 表。当某期 `AnalysisResult` 不存在或字段缺失时，跳过该期，`progression_note` 标注"该期 AI 分析未完成"。

### 4.2 计算逻辑

`longitudinal_service.py` 三个函数：

1. **`compute_metrics(patient_no, db)`**
   - 拉取该 `patient_no` 全部 `CaseRecord` (按 `is_deleted=False` 过滤)，按 `exam_date` 升序
   - 每期 join `AnalysisResult` 取 `hippocampusVolumeL/R`、`meanSUV`、`corticalThickness`、`ventricleVolume`、`mtaScore`
   - 写入/更新 `LongitudinalMetric` 表 (按 `patient_no + case_id` upsert)
   - 单期患者：写入快照但不计算变化率，`annual_rate_*` 为 null，`niaaa_stage` = "基线期，待随访"

2. **`compute_rates(series)`**
   - 对相邻两期算 `(后值 - 前值) / 间隔年`，间隔年 = `(exam_date[1] - exam_date[0]).days / 365.25`
   - 多期 (>2)：对每个相邻对计算"分期变化率"写入 `annual_rate_*` 字段 (取最近一对的值)
   - 全期线性回归 (OLS) 不在本期实现 (YAGNI)，留作第 4 期"AI 解释性"扩展
   - 单位：HV `cm³/年`、SUV `SUV/年`、皮层厚度 `mm/年`

3. **`classify_niaaa(metrics_series)`**
   - 依据 NIA-AA Research Framework 纵向进展阈值：
     - 海马体积年萎缩率 > 3%/年 (相对前值) → 加权 +2
     - SUVr 年降幅 > 2%/年 (相对前值) → 加权 +1
     - 皮层厚度年降幅 > 0.05 mm/年 → 加权 +1
   - 累加分数映射：0 = CN、1-2 = MCI、3-4 = AD-E、≥5 = AD-L
   - 单期数据不分级 (返回 "baseline")

### 4.3 API

新增路由文件 `ad-screen-backend/routers/longitudinal.py`：

- **`GET /case/longitudinal/{patient_no}`** → `{ timepoints: [...], rates: {...}, niaaaStage: "..." , available: true }`
- **`POST /case/longitudinal/{patient_no}/recompute`** (admin/researcher 角色) → 触发重新计算
- **`GET /case/{case_id}/longitudinal/timeline`** → 单病例入口 (反查 patient_no 后转发)

在 `main.py` 注册路由。

### 4.4 前端组件

新增 `ad-screen-frontend/src/views/longitudinal/LongitudinalCompare.vue`：

- **三联并排视图**：T1/T2/T3 同部位轴位切片 (默认海马层面 ~slice 70/128)，复用 `<img src="/api/case/{id}/imaging/slice?modality=MRI&idx=70">`
- **趋势折线图**：ECharts 三线图 (HV / SUV / 皮层厚度) 横轴 = exam_date，纵轴 = 各指标值；旁注 Δ/年 + 阈值参考线
- **NIA-AA 分级卡片**：彩色徽章 (CN 蓝/MCI 黄/AD-E 橙/AD-L 红) + progression_note 文本
- **入口**：`CaseDetailView.vue` 新增"纵向随访"标签页 (条件渲染：当 `case.patientNo` 检索到 ≥1 期时显示)

### 4.5 错误处理

| 场景 | 行为 |
|---|---|
| 单期患者 | API 返回 `{available: false, reason: "single_timepoint"}`，前端显示"暂无纵向对比，需 ≥2 期影像" |
| 该期 AI 分析未完成 | 跳过该期，`progression_note` 标注 |
| 病例不存在 / 已删除 | API 返回 404 |
| `exam_date` 缺失 | 跳过该期，日志告警 |
| 间隔 <30 天 | 仍计算但 `progression_note` 标注"间隔过短，变化率仅供参考" |
| 患者多模态不全 (有 MRI 无 PET) | 用 MRI 派生指标 (HV/皮层厚度) 计算，SUV 项置 null |

### 4.6 测试

`ad-screen-backend/tests/test_longitudinal_service.py`：
- 2 期场景：验证 `annual_rate_*` 计算正确
- 3 期场景：验证取最近一对
- 单期场景：`available=false`
- 缺失指标：跳过逻辑
- NIA-AA 阈值：构造 4 组数据验证分级映射

## 5. 子能力 2：DICOM 元数据增强

### 5.1 数据存储

**不新增 ORM 模型**。复用 `CaseRecord.scanner_info` 同款 JSON 字段思路，新增 `CaseRecord.dicom_meta` 字段 (Text, default="{}")。

字段内容 (JSON 字符串解析后为对象)：

```
PatientName / PatientID / StudyDate / StudyTime / SeriesDescription /
Modality / Manufacturer / FieldStrength / WindowCenter / WindowWidth /
SliceThickness / PixelSpacing (2D 数组)
```

### 5.2 上传时抽取

修改 `services/dicom_service.py::convert_dicom_to_nifti(dicom_dir, case_id)`：

- 在现有 DICOM→NIfTI 转换完成后，从首个 DICOM 文件 `pydicom.dcmread()` 抽取上述 12 个标签
- 返回 `dict` 给调用方 `case_router.upload_dicom()`
- `case_router` 把返回值写入 `case.dicom_meta` (JSON 序列化)
- DICOM 不可读 / 标签缺失：对应字段置 null，整体不抛异常 (降级)

### 5.3 API 扩展

`GET /case/{case_id}/imaging/meta` 返回新增字段：

```
dicomMeta: {
  patientName: "...", patientId: "...", studyDate: "...",
  studyTime: "...", seriesDescription: "...", modality: "MRI"|"PET",
  manufacturer: "...", fieldStrength: "3.0T",
  windowCenter: 40, windowWidth: 80,
  sliceThickness: 1.5, pixelSpacing: [1.0, 1.0]
}
```

历史病例 (无 DICOM 上传记录)：`dicomMeta: null`，前端回退到"元数据不可用"占位。

### 5.4 前端展示

`MedicalViewport.vue` 顶部新增 `<DicomMetaBar>` 子组件：

- 默认展示 6 核心字段：患者姓名 / ID / 检查日期 / 序列描述 / 窗宽窗位 / 层厚
- 点击"展开全部"显示完整 12 字段 (ElementPlus `<el-collapse>`)
- `dicomMeta: null` 时显示"元数据不可用 (历史病例或合成影像)"灰底占位

### 5.5 测试

`tests/test_dicom_meta.py`：
- 标准 DICOM 文件 → 验证 12 字段抽取正确
- 部分标签缺失 → 对应字段 null，无异常
- 无 DICOM 上传 → API 返回 `dicomMeta: null`
- 历史病例 → `imaging/meta` 仍正常返回其他字段

## 6. 子能力 3：MPR 高级工具

### 6.1 窗宽窗位调节

**后端**：`imaging_service.render_slice(nifti_path, idx, orientation, modality, wc=None, ww=None)` 新增可选参数：

- `wc` / `ww` 传入时，按 `(value - (wc - ww/2)) * 255 / ww` clamp 到 [0,255] 做强度窗
- 不传时维持现有默认窗 (按 `modality` 自动)

**API**：`GET /case/{case_id}/imaging/slice` 新增 `?wc=&ww=` 查询参数 (浮点)。

**预设**：前端定义常量 `WINDOW_PRESETS`：

```
MRI_T1: { wc: 40, ww: 80 }
MRI_T2: { wc: 80, ww: 200 }
MRI_FLAIR: { wc: 85, ww: 120 }
PET_FDG: { wc: 1.0, ww: 0.5 }
PET_AMYLOID: { wc: 1.2, ww: 0.6 }
CUSTOM: null  # 用户滑块自定义
```

**前端**：`MedicalViewport.vue` 工具栏新增 `<el-select>` 预设下拉 + `<el-slider>` (WC/WW 双轴)，实时刷新 `<img src>` 拼接 `&wc=&ww=`。

### 6.2 距离/角度测量

**扩展** `RoiAnnotationTool.vue` (已有 Canvas 2D 叠加层 + 球形/矩形/多边形 ROI)：

- 新增 `mode: 'distance' | 'angle' | 'roi'` 顶栏切换
- **距离**：两次点击 → 画线段，显示像素距离换算 mm：`length_mm = pixel_distance * pixelSpacing[0]` (从 `dicomMeta.pixelSpacing` 取，缺失时按 1.0 mm/px 默认并 UI 标注"无标尺信息")
- **角度**：三次点击 → 画两线段+顶点，显示角度 (°)
- **清除**：新增"清除测量"按钮，仅清测量层不清 ROI 层
- 像素间距派生：新增 composable `usePixelSpacing(caseId)` 从 `imagingMeta.dicomMeta.pixelSpacing` 派生

### 6.3 三平面十字线联动

**视图**：`ViewerView.vue` 当前是单视口 `sliceIdx` 联动。新增"三平面模式"开关 (默认关闭，开启后切换到三视口并排布局)：

- 三视口：轴位 (axial) / 矢状位 (sagittal) / 冠状位 (coronal)
- 三视口尺寸均为 128³ 体数据 (沿 `imagingMeta.sliceCount{Axial/Sagittal/Coronal}` 各自最大值)
- **十字线联动**：任一视口点击得到像素坐标 `(px, py)`，先换算为体素索引：`vox = floor(px / canvas_width * slice_count)` (canvas 等于 128 像素时退化为 `floor(px)`)。然后更新另两视口的切片索引：
  - 轴位点击 `(px, py)` → 体素 `(ax, ay)` → 矢状位 slice = ax，冠状位 slice = ay
  - 矢状位点击 `(px, py)` → 体素 `(sx, sy)` → 轴位 slice = sx，冠状位 slice = sy
  - 冠状位点击 `(px, py)` → 体素 `(cx, cy)` → 轴位 slice = cy，矢状位 slice = cx
- 像素→体素换算由 composable `useVoxelFromPixel(canvasSize, sliceCount)` 统一封装，三视口各自调用
- 十字线 Canvas 叠加 (跨两轴的细线，沿当前 sliceIdx 绘制，颜色 `#3b82f6` 50% 透明)

**API**：复用现有 `GET /case/{case_id}/imaging/slice?orientation={axial|sagittal|coronal}&idx=`，无需后端改动。

### 6.4 错误处理

| 场景 | 行为 |
|---|---|
| 影像不可用 (合成数据) | 三平面模式禁用 + 工具栏灰显，提示"真实影像不可用" |
| 窗宽窗位非法 (ww=0 或负值) | 后端校验，返回 400 |
| 像素间距缺失 | 测量工具显示"无标尺"标签，距离以像素显示 |
| 三平面切片越界 | clamp 到 [0, sliceCount-1] |

### 6.5 测试

`tests/test_imaging_service_mpr.py`：
- 窗宽窗位参数生效 (输出 PNG 像素值变化)
- 三平面切片各方向返回正确
- 越界 idx 自动 clamp
- `wc/ww` 非法值返回 400

前端 e2e (手动验证清单)：
- 三平面十字线点击联动正确
- 测量工具距离/角度数值合理
- 预设下拉切换后图像立即更新

## 10. 验收标准

1. 同一患者上传 2 期影像 → 触发 AI 分析 → 访问"纵向随访"页 → 展示三联切片 + 折线图 + NIA-AA 分级
2. 上传 DICOM → `imaging/meta` 返回 `dicomMeta` → 阅片器顶部展示 6 核心字段
3. 阅片器工具栏切换 MRI_T1 预设 → 图像立即按 WC=40/WW=80 窗显示
4. 测量工具点击两点 → 显示 mm 距离 (有像素间距时)
5. 三平面模式开启 → 任一视口点击 → 另两视口切片同步更新
6. 单期患者访问纵向页 → 显示"暂无纵向对比，需 ≥2 期"
7. 所有新增后端单测通过
8. TS 严格类型检查 (`npm run typecheck`) 通过

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 多期患者数据稀疏 (演示场景缺乏多期真实病例) | 保留模拟模式：纵向 service 在真实数据 <2 期时返回 `available:false`，不阻塞其他功能；测试用例构造合成多期数据 |
| `exam_date` 格式不统一 | 解析时支持 `yyyy-mm-dd` / `yyyymmdd` / `yyyy/mm/dd` 三种，统一归一化存储 |
| 窗宽窗位参数滥用导致服务端 OOM | 单张切片 PNG 渲染内存可控 (128² + numpy)，不预生成所有窗组合，按请求即时计算 |
| 三平面模式前端性能 (三视口同时刷新) | 仅在用户切换 slice 时刷新，避免 hover/连续拖动期间持续请求；引入 100ms 防抖 |
| `pixelSpacing` 缺失导致测量误导 | 强制 UI 标注"无标尺信息"，距离以像素显示 |
